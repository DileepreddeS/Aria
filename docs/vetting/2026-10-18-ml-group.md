# Vetting: the `ml` dependency group (Phase 2, steps 5 and 10)

Status: **decided 2026-10-18 (Dileep): option B, the weight-fetch design as written, the NLI pin as listed; for embeddings, Snowflake arctic-embed-s in place of all-MiniLM-L6-v2 (see the decision at the end).** Written 2026-10-18. Every figure below was read from
PyPI's JSON API and the Hugging Face Hub API on 2026-10-18; versions are resolved with the 14-day rule (uploaded
on or before 2026-10-04).

## What it is for

- **Step 5, Stage 4 `semantic_sim`** (RESUME_ENGINE §7, weight 0.25): a local sentence-embedding model, so
  candidate facts are compared with requirements without leaving the machine.
- **Step 10, 6b NLI entailment** (§9): a local NLI cross-encoder that checks the cited facts entail each bullet.

CI never loads either. Both sit behind interfaces with fakes (`aria_resume.match.embeddings.Embedder`, and the
NLI interface at step 10); the real models run in the eval and in production only. The group is optional
(`uv sync --group ml`).

## Recommendation

**Option B: `onnxruntime` + `tokenizers`, running the publishers' own ONNX exports, weights fetched once by an
explicit task, pinned by commit and SHA-256, and never downloaded by any library at runtime.**

| | Option A: `sentence-transformers` (torch) | **Option B: `onnxruntime` + `tokenizers`** |
|---|---|---|
| New packages (Windows / Linux) | 23 / 42 | **9 / 9** |
| Download size (Windows / Linux) | 217 MB / **3,099 MB** (PyPI's Linux torch pulls CUDA) | **37 MB / 51 MB** |
| CPU-only torch on Linux | needs a second package index (`download.pytorch.org`), a second supply-chain surface | not applicable |
| Runtime weight download | yes, by default (`from_pretrained` goes to the Hub, `main` branch) | **no code path that downloads** |
| What we write | almost nothing | tokenizing, mean pooling (MiniLM), softmax (NLI): ~60 lines, tested against the fake's contract |

Option A's convenience is real, but its default behaviour is the problem you named: the model loader fetches
weights from the Hub at first use, from a moving branch unless a revision is pinned, outside anything the lockfile
records. Option B never calls the Hub client: weights are files on disk, opened by path.

Checked by downloading each Windows wheel into an isolated folder, verifying it against PyPI's SHA-256, and
listing (not extracting or running) its contents: **no `.pth` files** (which would run at every interpreter
start), no executables, no `.data/scripts`. Wheels run no code at install. Console scripts are launchers that run
only when someone types their name.

**Build steps.** Every package above has a wheel for both our platforms, so no sdist is ever built. To make that
a rule rather than a fact of today's index, the group adds `no-build-package` entries in `[tool.uv]` for every
package with a native sdist (tokenizers, hf-xet, numpy, protobuf): if a wheel ever goes missing, the install
fails instead of compiling Rust or C from source.

**Two packages we do not call.** `tokenizers` depends on `huggingface-hub`, which brings `hf-xet` (a Rust client
for the Hub's storage). We load tokenizers from a local file (`Tokenizer.from_file`), so the Hub client is
installed but never imported by our code. The engine's boundary test already forbids network clients in its
product code; it would gain `huggingface_hub` and `hf_xet` explicitly.

**Telemetry.** onnxruntime's Windows builds include ETW telemetry that can be switched off
(`onnxruntime.disable_telemetry_events()`, present in 1.30.0's `__init__`). Our adapter calls it before creating
any session, and a test asserts it does.

Each new package gets a 14-day entry in `exclude-newer-package`, as the rule requires.

## Where the weights come from, and when

This is the part the lockfile does not cover, so it is made explicit:

1. **Only one command downloads:** `./tasks.ps1 models` (and `make models` for the eval job). It fetches each
   file from `https://huggingface.co/<repo>/resolve/<commit>/<path>` (a commit, never a branch), writes it under
   `%LOCALAPPDATA%\aria\models\<repo>@<commit>\`, and refuses any file whose SHA-256 differs from
   `engines/resume/aria_resume/models.lock` (committed, the hashes above). A mismatch deletes the download.
2. **Runtime never downloads.** The adapters open the ONNX file and `tokenizer.json` by path. They import neither
   `huggingface_hub` nor `transformers`; `HF_HUB_OFFLINE=1` is set in their process anyway, as a second lock. A
   missing or altered file is an error naming `./tasks.ps1 models`, never a fetch.
3. **CI downloads nothing.** Unit tests use the fakes. The eval job, when it runs the real models, runs
   `make models` first, so the fetch is a visible, hash-checked step in the log.
4. **Changing a model is a commit:** a new commit hash and new SHA-256s in `models.lock`, reviewed like a
   dependency bump, with the 14-day rule applied to the model commit's date. The pins above pass it: MiniLM's
   commit is from 2026-06-01, DeBERTa-v3-base NLI's from 2025-04-11.

## Decision (2026-10-18)

1. **Option B.**
2. **NLI:** cross-encoder/nli-deberta-v3-base as pinned above, xsmall as the eval's fallback, added at step 10.

   training sets; about 71% of the pretraining pairs are Snowflake's own web-search data, not itemised. HotpotQA,
   NQ and FEVER are CC BY-SA. Apache-2.0; commit
   `e596f507467533e48a2e17c007f0e1dacc837b33` (2024-12-04); `onnx/model.onnx` 133,093,492 bytes, SHA-256
   `579c1f1778a0993eb0d2a1403340ffb491c769247fb46acc4f5cf8ac5b89c1e1`; `tokenizer.json` 711,649 bytes, SHA-256
   `91f1def9b9391fdabe028cd3f3fcc4efd34e5d1f08c3bf2de513ebb5911a1854`; CLS pooling, 384 dimensions, a query prefix.
